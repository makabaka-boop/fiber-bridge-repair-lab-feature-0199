# 园区光纤环网 · 拓扑工作台

改造前找出**单条链路断开即隔离站点的薄弱段（桥 / bridge）**，再通过**试接一条虚拟备纤**
或**批量方案筛选**（一次评估上万个候选端点对）验证风险是否真正消除。React + TypeScript
单页工作台，Vitest 用**删边预言机**对随机小图做差分核对，Tarjan 桥算法在上限
（200 000 站点 / 400 000 链路）下 5 秒内完成且全程迭代、不递归。

---

## 1. 输入契约

页面接受粘贴或上传一个 **JSON 对象**，仅使用普通 JSON 基础类型（对象、数组、字符串、数字、
布尔、null）。结构：

```json
{
  "sites": ["S1", "S2", "S3"],
  "links": [
    { "id": "L1", "u": "S1", "v": "S2" },
    { "id": "L2", "u": "S2", "v": "S3" }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `sites` | **2–200 000** 个站点；编号**唯一、非空**。编号写为字符串；整数数字也会按其十进制文本接受（如 `7` 与 `"7"` 等同）。 |
| `links` | **0–400 000** 条无向链路；链路编号**唯一、非空**。 |
| `links[].u / v` | 端点编号**必须存在于 `sites`**；**禁止自环**（`u === v`）。 |
| 平行链路 | **合法**：同一对站点之间允许存在多条不同编号链路，它们彼此构成热备，均不算桥。 |
| 连通性 | **原图必须连通**（孤立站点 / 多分区将被拒绝）。 |

布尔、`null`、对象、数组、空串、`NaN`/`Infinity` 均不能作为编号。

> 编号的“字节序”按其 **UTF-8 编码字节**逐字节比较（等价于 JS 字符串默认字典序，
> 实现与测试均有说明和差分验证）。注意这是字节序而非数值大小：`L10 < L2`。

### 输出语义（基线）

* 按**链路编号 UTF-8 字节序**列出**全部脆弱链路（桥）**；
* 每条给出**断开后两个连通块中较小者的站点数**（`min(子树, n − 子树)`）；
* **不输出任何站点清单**（表格仅展示编号、端点与较小侧站点数，供核对）。

### 试接（虚拟备纤）

从**现有站点**中选择**两个不同端点**试接一条虚拟备纤：

* 页面**独立**给出试接后 **仍脆弱** 的链路，以及相对基线 **已消除** 的链路；
* 试接**不改写基线**：基线对象在导入时固定，试接只读取并派生新结果；
* **非法导入**保留上次有效拓扑并显示明确错误；**非法试接**保留上次试接结果并显示明确错误。

一条新边 `(a,b)` 恰好消除桥树中 `a↔b` 路径上的全部桥——长链、大环、平行链路均得到
精确且稳定的结论（由随机差分测试锁定）。

### 批量方案筛选

粘贴 **1–100 000** 项的 **JSON 数组**，每项仅含 `a`、`b` 两个站点编号（规则同单次试接）：

* **整批先校验**结构、字段、端点存在且互异；任一项非法即**按下标报错、整批拒绝**，
  保留上次批量结果，且不改写基线与单次试接结果；空批次、额外字段、超限均整体拒绝；
* 全批合法后核心接口才生成结果并**一次提交**给页面，成功时**整体替换**，
  **重复候选按原序保留**；
* 结果按**输入下标**分页展示每个端点对**可消除的基线脆弱链路数量**，不展开链路清单；
* Analyzer 在合法导入时基于 Tarjan 父树与桥标记构建**只读桥前缀 + 二进制提升索引**，
  逐项以**最近公共祖先** O(log V) 计数——不循环调用单次试接、不逐项分配 links 长度缓冲、
  不扫描全部链路。200 000 站点长链 × 100 000 组查询的构建与整批计数在 5 秒内完成（Vitest 锁定）。

## 2. 本地开发

```bash
npm ci
npm run dev        # 开发服务器（Vite，默认 5173）
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 本地预览生产构建
npm run test       # Vitest 全量测试（含删边预言机差分）
npm run typecheck  # 仅类型检查
npx tsx src/core/perf.ts   # 上限数据（200k/400k）性能基准，断言 < 5000ms
```

测试构成：

* `src/core/utf8.test.ts` — UTF-8 字节序与真实 `TextEncoder` 编码的差分；
* `src/core/parse.test.ts` — 输入契约的各类合法 / 非法情形；
* `src/core/analysis.test.ts` — 生产 Tarjan 与**删边预言机**在随机小图上的逐项核对
  （桥集合、较小侧站点数、试接后仍脆弱 / 已消除），以及长链、大环、平行链路、蝴蝶结等典型拓扑；
* `src/core/batch.test.ts` — 批量方案筛选：随机多重小图上每项计数与 `trial(a,b).removed.length`
  一致（删边预言机核对）、末项非法无部分结果、整批校验各非法情形，以及
  **200 000 站点长链 × 100 000 组查询**的距离计数与 5 秒时限（全程迭代不递归）；
* `src/ui/App.test.tsx` — 导入→基线→试接→批量筛选→非法操作保留上次结果的端到端交互。

> 所有结论均由当前输入实时计算，**不存在固定结果 / 固定答案**。

## 3. Docker Compose

### 发布页面（`web`，长期运行）

宿主机端口用可覆盖的 **`WEB_PORT`** 控制（默认 `8080`）：

```bash
docker compose up --build web                 # 默认 http://localhost:8080
WEB_PORT=9000 docker compose up --build web   # 覆盖为 9000
# 或复制 .env.example 为 .env 后修改 WEB_PORT
```

镜像为多阶段构建：Node 构建静态资源后，用零依赖 Node HTTP 服务器发布（带 SPA 回退）。

### 一次性验收（`verify`）

`verify` 是**一次性服务**：依次执行类型检查、Vitest 全量测试、上限 5 秒性能基准，
**全部通过则以退出码 0 结束**，不发布端口、不重启：

```bash
docker compose --profile verify build verify
docker compose --profile verify run --rm verify
```

## 4. 算法与工程要点

* **桥检测**：Tarjan 无向图桥算法，`low[v] > disc[parent]` 判桥；**平行链路通过“只跳过
  通向父顶点的同一条边”正确处理**（平行的另一条作为回边降低 low 值）。
* **较小侧站点数**：DFS 同时统计子树规模 `subtree[v]`，桥断开后两侧为 `subtree[v]` 与
  `n − subtree[v]`，取较小值。
* **试接消险**：桥缩点得到桥树；新边覆盖的恰为两端点在 DFS 树上的路径桥，用父边与深度
  求 LCA 路径，O(V) 派生。
* **批量筛选**：合法导入时基于 Tarjan 父树与桥标记构建只读**桥前缀**（根到各顶点的
  桥数前缀）与**二进制提升索引**；每项候选以 LCA 求得
  `pref[a] + pref[b] − 2·pref[lca]`，O(log V) 计数，与单次试接结论逐项一致。
* **不撑爆调用栈**：Tarjan 与连通性 / BFS 全部为**显式栈 / 显式队列迭代实现**，
  200 000 个站点的纯长链也不会递归（已实测）。
* **性能与内存**：邻接表、DFS 缓冲均使用紧凑类型化数组（`Int32Array` / `Uint8Array`），
  避免约 80 万邻接记录装箱；上限数据解析 + 基线 + 试接合计约 2 秒（见 `perf.ts`，预算 5 秒）。

## 目录结构

```
src/
  core/            纯逻辑（无 DOM 依赖，可独立测试）
    types.ts       数据类型与错误
    utf8.ts        UTF-8 字节序比较
    parse.ts       导入契约解析与校验（含连通性）
    analysis.ts    Tarjan 桥分析器 + 试接 + 批量筛选（LCA 索引，迭代实现）
    oracle.ts      删边预言机（仅测试用朴素参考实现）
    testGraph.ts   随机连通多重图生成器（仅测试用）
    *.test.ts      Vitest 差分 / 契约测试
    perf.ts        上限性能基准
  ui/              React 工作台（导入、基线复核、试接核对、分页表格）
docker/            零依赖静态服务器
Dockerfile         web 镜像
Dockerfile.verify  一次性验收镜像
docker-compose.yml web + verify(profile)
```
